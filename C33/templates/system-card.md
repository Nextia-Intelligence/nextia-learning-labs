# System card

A system card says what an AI system is for, what it may do and who answers for it, on one or two pages. Its readers: staff who use the system, the board, an auditor, the next owner. Keep it next to the system's other records, and update it in the same change that changes the system: then it never needs a separate "documentation day".

| Field | Write |
|---|---|
| Name, ID, version | |
| Purpose | What it does, for whom |
| Not for | Uses that are not allowed |
| Accountable owner / technical owner | Named people |
| Approver of actions and changes | Named people, with limits |
| Tier and date of the tier | From the risk-tier table |
| Users / people affected | |
| Data in, data out, where data goes | |
| Model and vendor | Name and version; vendor's model information, if any |
| What it may do alone | suggests, proposes with approval, acts alone |
| Evaluation | The last result, the date and where the record is |
| Known limits and failures | From the evaluation and from incidents |
| Monitoring and pause conditions | |
| Impact assessment | Needed? Where is it? |
| Links | Decision records, change log, incidents, vendor check |
| Next review | |
