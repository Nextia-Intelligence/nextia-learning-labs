# The design pack

Every decision of the capstone is written down here, one file per step. The templates are in `templates/`: copy a template next to this file when its lesson starts, and fill it.

| File | Lesson | What it decides |
|---|---|---|
| `project-brief.md` | Problem and audience | one user, one decision, the documents, the non-goals, the track |
| `acceptance-criteria.md` | Acceptance criteria | testable behaviour, quality thresholds, access rules, budget |
| `evidence-plan.md` | Plan the evidence | the proof for every claim, and the held-out questions |
| `data-card.md` | Synthetic data pack | where the documents come from, and their deliberate difficulties |
| `architecture.md` | Architecture and contracts | components, API, database, ingestion states, retrieval metadata |
| `threat-and-cost.md` | Threat and cost review | trust boundaries, threats, isolation rules, the budget |
| `evaluation-report.md` | Run held-out tests to Document trade-offs | results, error categories, baseline against candidate |
| `demo-script.md` | Demo narrative | the five-minute story, with a failure case and a trade-off |
| `portfolio-checklist.md` | Repository handoff | every claim and its evidence |
