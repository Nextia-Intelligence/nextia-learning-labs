# Experiment-review checklist (one page)

*Module 5, lesson 3. Use it on any experiment report or demo. You do not need to read code. For each line, write what you found, or "missing". A missing line is a question, not a failure: ask for it.*

**Report:** **Author:** **Decision it supports:**

| # | Ask for | What you found |
|---|---|---|
| 1 | **The decision.** What will we do differently if the result is good? If it is bad? | |
| 2 | **The baseline.** What does today's way (or the simplest option) score on the same examples? | |
| 3 | **The evaluation set.** Which examples, how many, who labelled them, and were they kept apart from the work? | |
| 4 | **The measure that matters to users,** not only a technical one (a training loss or "format valid" is not the user's result). | |
| 5 | **The groups.** Results for the rare and risky cases (safety, other languages, edge cases), not only the average. | |
| 6 | **The range.** How sure is the result? How many examples, how many runs? | |
| 7 | **Error examples.** At least five real failures, read by a person. | |
| 8 | **Cost.** Per unit and per month, at our volume, with people's time counted. | |
| 9 | **What was not tested,** and what would change the conclusion. | |
| 10 | **Can it be repeated?** The data version, the settings and the run are saved. | |
